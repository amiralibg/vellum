Q3 infrastructure report

We moved every service onto one VPS cluster, cut hosting cost by 38%, and had one incident that customers noticed.

7 min read · 1,420 words

Summary

This quarter was about consolidation. In July we were paying three providers for overlapping work. By the end of September everything ran on two Hetzner machines managed through Dokploy, with Postgres on a dedicated volume and nightly off-site backups.

  • Monthly hosting fell from €412 to €255.
  • p95 API latency improved from 340 ms to 190 ms.
  • One customer-visible incident, on August 14, lasting 22 minutes.

Uptime & incidents

Measured uptime across public endpoints was 99.94%, against a target of 99.9%.

The August incident was a disk filling up with unrotated logs. Nothing was wrong with the code; we had simply never told Docker to stop keeping everything.

The fix was a one-line change to the daemon config, now applied to every host:

# /etc/docker/daemon.json
{
  "log-driver": "json-file",
  "log-opts": { "max-size": "20m", "max-file": "5" }
}

Cost

Most of the saving came from dropping the managed database. Running Postgres ourselves adds about two hours of work a month, which we think is a fair trade at this size. See the backup runbook for how restores are tested.

What changed

Deploys

Every app now builds from a Dockerfile in its repo and deploys on push to main. Rollbacks are a single click in Dokploy.

Monitoring

Each service exposes /health, polled every 30 seconds. Alerts go to one Telegram channel instead of three inboxes.

Plan for Q4

  1. Move object storage off S3 to the same provider.
  2. Add a staging environment that mirrors production.
  3. Test a full restore from backup once a month, not once a quarter.
